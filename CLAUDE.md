# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

StayT is a task-aware **Android** app blocker: Expo SDK 57 (React Native 0.86, TS) + a custom Kotlin accessibility service. iOS is out of scope. No backend — everything is on-device. Product spec and milestone history live one level up (`../ARCHITECTURE.md`, `../IMPLEMENTATION.md`, `../AGENTS.md` for the agent/skill workflow, `../MIMO_ONE_SHOT_PROMPT.md` for design direction). `Context.md` is a running session log, not a spec; prefer `ARCHITECTURE.md` and the ADRs when they disagree.

## Commands

```sh
npx tsc --noEmit                 # the only static check (no lint, no unit-test runner)
npm run check:native-mirror      # run after ANY native change (see below)
npx expo start                   # dev server for an installed dev-client build
npx expo prebuild --platform android --no-install   # regenerate android/ from modules/blocker
npx eas build -p android --profile preview          # APK build (preferred; local Gradle builds are unreliable here)
adb install -r <file>.apk        # install on the test device (real device required — OEM quirks)
maestro test .maestro/                   # all E2E flows
maestro test .maestro/session.yml        # single flow
```

Maestro flows need an installed build (`eas build --profile e2e-test`) and permissions granted manually once; `BlockedInterstitial` and purchase paths aren't covered. See `tests/test-summary.md`.

## Native code: single source of truth

- **Edit Kotlin/resources only in `modules/blocker/src/main/`.** `android/` and `ios/` are gitignored and regenerated by `expo prebuild` via `modules/blocker/plugin.js`, which copies the `.kt` files and `res/` into `android/app/...` and injects manifest entries/strings (and strips `SYSTEM_ALERT_WINDOW`). Edits made directly under `android/` are lost.
- EAS runs prebuild itself (`eas-build-post-install` script).
- New resource dirs/strings may need wiring in `plugin.js`; `scripts/check-native-mirror.sh` diffs the two trees and fails on drift.

## Architecture

**Enforcement loop.** `StayTAccessibilityService.kt` watches foreground-app changes. For a blocked package it shows a full-screen `TYPE_ACCESSIBILITY_OVERLAY` over the app (or, via a `getWindows()` scan on every window change, a cover pinned to a blocked split-screen / pop-up / PiP window — ADR-0009) (back to task / close / more options → JS `BlockedInterstitialScreen`) and emits a blocked-attempt event that JS only logs. If the overlay can't be added it falls back to `performGlobalAction(HOME)` + a heads-up "tap to return" notification. The ongoing session note (themed, native chronometer, play/pause) is a plain notification. There is deliberately **no SYSTEM_ALERT_WINDOW, no full-screen intent, no foreground service, no exact alarms** — see `docs/adr/0002`, `0006`, `0007`, `0008`, `0009` before changing any of that (Play-review safety + Android BAL restrictions).

**Blocking model.** Default is a *blocklist* (`blockedPackages`: apps in the set bounce). A task can switch to *allowlist* mode (only `allowlist` stays usable, with a system safelist of launchers/dialer/systemui/Settings never blocked). On top of that: per-app budgets, feed filters, blocked domains, strict mode, schedules. Collision rule: hard block wins.

**JS ↔ native boundary.**
- `src/native/AppBlocker.ts` — the only typed wrapper over `NativeModules.AppBlocker` (`AppBlockerModule.kt`). Screens don't touch `NativeModules` directly.
- `src/native/blockedContract.ts` — the single seam for deep-link scheme/host/query keys/package regex. Kotlin mirrors these as companion constants in `StayTAccessibilityService`; change both together, never hardcode elsewhere.
- `src/navigation/blockedEntry.ts` — dedups interstitial entry between the event emitter and deep links.
- Bridge inputs are clamped/validated on the Kotlin side (ADR-0004); rule lists read on the event path are CopyOnWrite.
- **Durable intent / fail-closed:** native mirrors desired blocking state into SharedPreferences and re-arms on service connect, so process death and reboot keep enforcing. When in doubt, keep blocking.

**Other native pieces** (all in `modules/blocker`): `ScheduleAlarm*` (inexact AlarmManager schedules + boot receiver), `StayTTileService` (Quick Settings tile), `StayTWidgetProvider` + `WidgetData` (home widget reading a prefs mirror written from JS via `src/widget/widgetSync.ts`).

**JS side.** `App.tsx` holds the native-stack navigator, font loading/splash, launch routing (onboarding → permissions → tasks) and the blocked-attempt listener. `src/storage/store.ts` is the single AsyncStorage store (`@stayt_*` keys) for tasks, sessions, attempts, preferences, schedules, budgets, etc.; types in `src/types.ts`. Pro gating is in `src/billing/pro.ts` (`expo-iap`, one-time `stayt_pro` product).

**Theming.** All colors/typography/spacing come from `src/theme/tokens.ts` via `useTheme()` (`ThemeContext.tsx`); light + pure-black dark modes. Fonts: Anton (display), Space Grotesk (headings/labels), Inter (body). Design rules: no emojis, minimal line icons (`components/icons.tsx`), Duolingo-style gamified accents on a calm base (`../DUOLINGO_STYLE_REFERENCE.md`). Mascot is the owl (`assets/mascot/`, `WitheringOwl.tsx`).

Terminology used in comments and ADRs (seam, durable intent, fail-closed, safelist, BAL, single-surface rule) is defined in `docs/adr/GLOSSARY.md`. Record significant native/enforcement decisions as a new ADR in `docs/adr/`.

## Escalation

Per `../AGENTS.md`: if the native/JS boundary or data model is ambiguous, stop and ask rather than guess. Android accessibility/OEM behavior (`TYPE_WINDOW_STATE_CHANGED`, `performGlobalAction`, battery optimization) must be checked against current Android docs, not memory.
